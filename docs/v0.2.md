# v0.2 — Service Registry

## 这一章解决什么问题

上一章的 `Context` 是空的，没法往里面放任何东西。这一章让它能存、能取——`Context` 第一次真正具备"容器"的行为，而不只是一个能被 `new` 出来的空壳。

## 上一版本有什么不足

`class Context {}` 没有任何字段或方法，连最基本的"注册一个能力、再把它找回来"都做不到。想用 `greeter` 这个能力，只能自己 `import` 具体实现、自己 `new`——调用方因此被绑死在某一个具体实现上，换一个实现就要改调用方的代码。

## 本章设计

最小的 API：

```ts
ctx.provide('greeter', greeter)
ctx.get('greeter')
```

内部用一个 `Map<string, unknown>` 存所有 service，**故意不用泛型**——先把 Runtime 模型讲清楚，类型安全留到后面章节，等模型稳定了再讨论。

两个需要显式定义、并写进测试的边界行为：

1. **获取不存在的 service**：返回 `undefined`，不抛异常。这样调用方用 `if (!ctx.get('greeter'))` 就能优雅处理"能力暂时不存在"，不需要 try/catch。
2. **重复 `provide` 同一个 name**：直接覆盖，后一次生效。这是**教学版策略**——真实做法可能会走更复杂的路径（比如隔离/影子机制），但那套机制现在还没引入，先用最简单的规则让模型能运作起来。

## 最小实现

`src/context.ts`，`Context` 从空类变成：

```ts
export class Context {
  private services = new Map<string, unknown>()

  provide(name: string, service: unknown): void {
    this.services.set(name, service)
  }

  get(name: string): unknown {
    return this.services.get(name)
  }
}
```

## 测试

```ts
describe('Service Registry', () => {
  it('service 可以注册并取回', () => {
    const ctx = new Context()
    const greeter = { greet: (name: string) => `Hello, ${name}!` }
    ctx.provide('greeter', greeter)
    expect(ctx.get('greeter')).toBe(greeter)
  })

  it('service 可以被调用', () => {
    const ctx = new Context()
    ctx.provide('greeter', { greet: (name: string) => `Hello, ${name}!` })
    const greeter = ctx.get('greeter') as { greet(name: string): string }
    expect(greeter.greet('Alex')).toBe('Hello, Alex!')
  })

  it('获取不存在的 service 时返回 undefined', () => {
    const ctx = new Context()
    expect(ctx.get('does-not-exist')).toBeUndefined()
  })

  it('重复 provide 同一个 name 时，后一次覆盖前一次', () => {
    const ctx = new Context()
    ctx.provide('greeter', { greet: () => 'first' })
    ctx.provide('greeter', { greet: () => 'second' })
    expect((ctx.get('greeter') as any).greet()).toBe('second')
  })
})
```

运行：

```bash
npm test
```

```text
      Tests  6 passed (6)
```

## Demo

```ts
import { Context } from './src/context'

const ctx = new Context()

ctx.provide('greeter', {
  greet(name: string) {
    return `Hello, ${name}!`
  }
})

console.log((ctx.get('greeter') as any).greet('Alex'))
```

实际输出：

```text
Hello, Alex!
```

## 这一章之后

- `get()` 返回类型是 `unknown`，每次用都要手动 cast——类型安全留到以后再解决。
- 没有"卸载"能力——`provide` 了就一直在，下一章才加 `remove`。
- 没有"谁提供了这个 service、什么时候提供的"这类追踪信息，出错了也无从排查——这是后面 Plugin/Effect 章节要解决的。

## 思考题

1. `get()` 不存在时返回 `undefined` 而不是抛异常，这个选择对调用方写代码的方式有什么影响？如果反过来选择"抛异常"，调用方的代码会变成什么样？
2. "重复 provide 直接覆盖"是教学版策略。设想一下：如果两个不相关的模块不小心用了同一个 service 名字，这个策略会导致什么后果？真实系统里应该怎么避免（提示：命名冲突检测 vs 完全不同的隔离机制，你会选哪个方向）？
3. 这一章的 `get()` 返回 `unknown`，调用方每次都要 `as` 断言。如果现在就想让它变成类型安全的（比如 `ctx.get<Greeter>('greeter')` 返回 `Greeter | undefined`），大概需要怎么改？这个改动会不会影响 `services` 内部用 `Map<string, unknown>` 存储这件事本身？
