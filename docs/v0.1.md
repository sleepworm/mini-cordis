# v0.1 — Context

## 这一章解决什么问题

在能往 Context 里塞任何东西（Service、Plugin、Event……）之前，先要有 Context 这个"容器"本身存在。这一章只回答一个问题：`new Context()` 应该是什么。

## 本章设计

刻意做成**空类**：

```ts
export class Context {}
```

不给它任何字段、任何方法。原因是：如果一上来就往 `Context` 里塞 Service Registry、Event Bus 等等，就没法讲清楚"Context 本身是什么"和"Context 上挂了什么能力"这两件事的区别。先把"容器"这个概念单独立住，后面每一章往里面加一种能力，能清楚看到每种能力是**加上去的**，不是 Context 与生俱来的。

## 最小实现

`src/context.ts`：

```ts
export class Context {}
```

`src/index.ts`：

```ts
export const VERSION = '0.1.0'

export { Context } from './context'
```

## 测试

```ts
import { describe, expect, it } from 'vitest'
import { Context } from '../src/context'

describe('Context', () => {
  it('can be constructed', () => {
    const ctx = new Context()
    expect(ctx).toBeInstanceOf(Context)
  })
})
```

npm test

## Demo

```ts
const ctx = new Context()
```

`ctx` 目前没有任何可观察的行为——这正是本章的验收标准：**Context 存在，但还没有能力**。

## 这一章之后

- `Context` 还不能存取任何东西——下一章加 Service Registry。
- `Context` 还没有 `dispose()`、没有 Plugin、没有 Event，全部留到后面。
